# Omni / Flow Omni 按次计费更新

2026-09-28，两个插件已在现有 New API `v1.0.0-rc.40` 服务上切换为 `1.1.0`。没有改镜像、重启容器、改变通道绑定或调用真实生成接口。

## 变更

- `oaireg-omni`：用量改为 `requests: 1`，移除默认 4 秒及 size 计费档位。视频请求本身的参数保持不变。
- `oaireg-flow-omni`：新增 `requests: 1`，保留生成方式分类，补充文生视频、图生视频、视频编辑中文标签。
- 单位为 `count`，中文标签“次”，字段名称“生成次数”。提交和完成阶段均固定为 1，外部提供的次数、秒数不会改变这一值。
- 已定价的 `omni-fast-no-water` 保持 3.45 USD/次，公式改为 `tier("request", u("requests") * 3.45)`。现有分组倍率未变。
- `omni-fast` 和 `flow-omni-1.1-flash` 原本没有配置价格，本次继续保持未定价，未套用其他模型的价格。

## 部署过程和回退

由于后台浏览器工具未能启动，且管理员没有现成管理访问令牌，本次通过已授权 SSH，在数据库事务内执行更新，并使用服务现有的配置同步及插件热加载机制生效。更新前确认两个插件没有运行中任务。

先备份插件和定价配置，将旧固定收费公式等价化为不引用 seconds 的常数；待配置同步后激活已通过原生校验的新版本；待插件同步后改成引用 requests 的最终公式。每步检查原值，避免覆盖并发修改。

旧版 1.0.0 保留为非活动版本。服务器备份：

```text
/opt/1panel/apps/new-api/new-api/data/lumora-omni-count-before-20260928.json
/opt/1panel/apps/new-api/new-api/data/lumora-omni-count-upgrade-20260928.json
```

回退时也必须配套处理公式：先将按次数公式改成等价常数并等待缓存同步，再激活 1.0.0；不要直接把仍引用 requests 的公式交给旧版插件。先检查正在运行的任务和期间发生的价格调整，不要整份覆盖其他模型定价。

同日用户在截图中明确指定 Flow 为 5.8、Omni Fast 为 3.25，沿用当前 USD 单位。已在事务内增加以下两个模型的 `tiered_expr` 定价：

| --- | --- | --- |

# 批次内重新生成失败项

批次详情 `/app/job-batches/{id}/result` 顶部提供“重新生成失败项”，每条生成失败的任务也提供“重新生成”。下载失败只提供“重新下载”。手机使用卡片排列，操作无需横向滚动。

重做留在原批次和原条目位置。后台保留旧失败记录，通过 `jobs.retry_of_job_id` 关联新的执行记录；批次统计、普通用户任务列表只显示每条的最新尝试，不创建新批次、不增加批次条数。最新条目可打开上次失败记录。历史记录的任务编号可用于追溯，ZIP 下载仍从原批次进行。

预览接口返回本次确认的失败任务 ID 和预占额度，提交只处理这些 ID，不自动扩大范围。重做复用原模型、通道、提示词、画幅、时长、参考素材；通道停用、模型配置变化、当前风控不通过或本地素材缺失时拒绝。模型改变时需在创作页重新选择。

每次重做使用现有额度预占/提交扣费流程；原失败任务的账目保持不变。额度不足等校验失败整批回滚。用户和源任务行锁配合唯一约束防止并发重复提交；请求重放只返回原先创建的执行记录，即使该记录后来也失败，重放仍不会创建第三次执行。再次重做须明确选择最新失败项。重新下载不生成、不扣生成额度。

发布先备份数据库，执行 `alembic upgrade head`（0025_job_regeneration），再启动新版服务。自动测试和浏览器验证使用隔离数据，不调用真实视频生成服务。PostgreSQL 并发验证脚本仅允许在名为 `regeneration_test` 的一次性测试数据库运行。

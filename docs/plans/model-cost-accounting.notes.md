# New API 逐任务成本接入记录

日期：2026-10-21。当前为本地代码变更，尚未部署到运行中的 NAS。

## 已实现

- Worker 在 New API 的 Grok、Omni、Flow 任务提交并取得远端任务 ID 后，建立待计费记录；最近 48 小时内已有远端 ID 的任务由 Worker 补登记。
- 独立查账线程使用该任务原本的生成令牌读取 `/v1/videos/{task_id}`、`/api/log/token` 与 `/api/status`。只对远端 `completed` 的任务记成本；失败任务排除。任务生成中也保存预扣日志，避免近期 1000 条日志窗口滚动后丢失首笔扣费。
- 按日志 `other.task_id` 精确匹配远端任务 ID；消费额度相加、退款额度相减，保存当笔表达式、用量事实、倍率与原始日志请求 ID。额度除以首次查得的 `quota_per_unit`，金额以 Decimal 存为 USD。重复轮询不会重复记账；迟到的差额生成修订记录。
- 用 New API `completed_at` 按上海日期归属。成本记录不依赖任务或用户外键，删除任务或用户后仍可汇总。
- 主管理员的每日用量页面、JSON 和 XLSX 显示成功任务成本与待计费任务数，并可按日或任务查看明细。副管理员不可读取这些管理报表的成本字段；新的“使用日志”页面按角色单独授权，副管理员可看未被隐藏用户的合计与明细。
- 迁移 `0027_job_costs` 新建 `job_costs`、`job_cost_revisions`；容器启动脚本已有 `alembic upgrade head`，部署时会先迁移再启动 Worker。

## 验证

- 用用户提供的测试 New API 令牌只读调用新查账函数：一条已完成的 Grok 720p、15 秒任务匹配 1,950,000 额度；当时 `quota_per_unit=500000`，得 3.90 USD，日志表达式包含 720p 档位每秒 0.26 USD。没有发起生成或扣费。
- 本地模拟测试覆盖任务 ID 精确匹配、预扣日志跨窗口保留、退款差额、重复轮询、失败不计费、上海日期和报表权限。
- Alembic 从三种旧数据库修订升级到 `0027_job_costs` 的现有测试通过；PostgreSQL 离线 DDL 生成通过。本轮使用日志和创作界面改动之前，全套 206 个单元/集成测试通过。尚未在真实 NAS 数据库执行迁移，也未在运行中的 NAS 上验证 Worker。

## 当前边界

- 用户再次确认：**最终生成失败的任务默认不计入成本**。失败记录可用于追踪，但金额不进入日成本或总成本。`pending` 记录在生成中或费用尚未核实时也不计入金额；最终确认失败后转为 `excluded`。上游已确认生成成功、只是本地下载失败的任务，按既定“只统计成功生成”口径计入成本。
- 使用日志现已区分“生成中”与“成功待核对”，并显示失败待排除状态。主管理员可将成功待核对记录加入现有查账队列立即重查；金额仍以已结算记录为准。
- 仅上述 New API 视频渠道自动取账；其他直连渠道的手工单价仍按原计划另做。
- 普通生成令牌只返回最近最多 1000 条日志。若任务在首次捕获前已被挤出窗口，记录会保留为待计费并显示错误，不会用现价猜金额。历史任务只自动补登记最近 48 小时内的记录。
- 目前只接受 New API 的 USD 额度展示配置；其他币种会标记待计费。首次查询即冻结 `quota_per_unit`；若站点恰在提交与首次查询的几秒内修改此换算值，需人工核对。
- 已结算任务在完成后两天内每 15 分钟复查一次，以捕获补扣或退款；更晚出现的差额需要人工补账流程或延长复查窗口。
